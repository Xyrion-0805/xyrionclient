# AI 自动回复

在“设置 → Xyrion”中配置 AI 自动回复。默认关闭；开启后，仅在联机游戏中响应其他玩家对自己名字的提及。主号名字及服务器上实际显示的自己名字参与匹配；dummy 名字仅在 dummy 已连接时参与匹配。

## 双协议配置

接口地址必须是**完整请求 URL**，包含请求路径，不能只填写域名或 API 基地址。选择协议不会自动替换地址或模型，请同时检查这两个字段。

需要认证的服务，请在设置页的“API 密钥”中自行填写。以下示例省略密钥设置；无认证的本地兼容服务可以留空。示例可在客户端本地控制台执行。

### OpenAI 兼容 chat/completions

使用默认模型的配置示例：

~~~text
xc_ai_enabled 0
xc_ai_protocol 0
xc_ai_endpoint "https://api.openai.com/v1/chat/completions"
xc_ai_model "gpt-4.1-mini"
xc_ai_prompt "你是游戏聊天助手。请用简短自然的中文回复玩家，只输出一条聊天回复，不输出命令。"
xc_ai_context 1
xc_ai_context_turns 6
xc_ai_cooldown 5
xc_ai_enabled 1
~~~

支持 OpenAI 兼容协议的其他服务也使用协议值 0，将地址和模型替换为该服务提供的值。系统提示词作为 messages 中的 system 消息发送。

### Anthropic messages

先将下面的 YOUR_ANTHROPIC_MODEL 替换为服务实际支持的模型标识，再执行配置：

~~~text
xc_ai_enabled 0
xc_ai_protocol 1
xc_ai_endpoint "https://api.anthropic.com/v1/messages"
xc_ai_model "YOUR_ANTHROPIC_MODEL"
xc_ai_prompt "你是游戏聊天助手。请用简短自然的中文回复玩家，只输出一条聊天回复，不输出命令。"
xc_ai_context 1
xc_ai_context_turns 6
xc_ai_cooldown 5
xc_ai_enabled 1
~~~

该协议把系统提示词放在顶层 system 字段；messages 仅包含 user / assistant 对话。请求带有 anthropic-version: 2023-06-01，并设置 max_tokens。兼容代理可使用自己的完整 messages 请求地址。

### 本地无认证兼容服务

例如本地服务提供 http://127.0.0.1:8080/v1/chat/completions 时，可使用：

~~~text
xc_ai_enabled 0
http_allow_insecure 1
xc_ai_protocol 0
xc_ai_endpoint "http://127.0.0.1:8080/v1/chat/completions"
xc_ai_model "YOUR_LOCAL_MODEL"
xc_ai_enabled 1
~~~

YOUR_LOCAL_MODEL 也需要替换为本地服务实际提供的模型名。“API 密钥”可在设置页留空。HTTP 地址需要显式启用 http_allow_insecure；使用 HTTPS 时不需要这项设置。Anthropic 兼容的本地 messages 服务同样支持空密钥。

## 配置字段

| 控制台配置 | 设置页用途 | 默认值／范围 |
| --- | --- | --- |
| xc_ai_enabled | AI 自动回复开关 | 0；0 / 1 |
| xc_ai_context | 记住聊天上下文 | 0；0 / 1 |
| xc_ai_protocol | 请求协议 | 0：OpenAI 兼容；1：Anthropic |
| xc_ai_endpoint | 完整接口 URL | OpenAI chat/completions 地址；最多 1023 字节 |
| xc_ai_model | 服务支持的模型名称 | gpt-4.1-mini；最多 127 字节 |
| xc_ai_prompt | 系统提示词 | 简短中文游戏聊天指令；最多 2047 字节 |
| xc_ai_context_turns | 每位玩家保留的完整对话轮数 | 6；1–32 |
| xc_ai_cooldown | 接收新提及及请求／回复的冷却秒数 | 5；0–120 |

字节上限不等于中文字符数。URL 中的非 ASCII 主机名或路径需要转换为可请求的 URL 编码形式。两种协议都发送非流式文本请求，返回的错误、工具调用和无效 JSON 不会作为聊天回复发送。

## 名字提及与称呼前缀

名字按完整 UTF-8 文本精确匹配，区分大小写；不会将不同大小写、同形字或不同 Unicode 组合形式自动视为同一个名字。名字前后需要明确边界，避免在更长的名字、邮箱或标识符中误触发。空格、常见中英文标点可作为边界。

假设自己的实际名字是“小明”，下列消息的处理为：

| 其他玩家发送的消息 | 发送给 AI 的本轮 user 正文 |
| --- | --- |
| [小明]: 你好 | 你好 |
| 小明: 你好 | 你好 |
| @小明: 你好 | 你好 |
| @小明：你好 | 你好 |
| [小明]：　你好 | 你好 |
| [发言者]: [小明]: 你好 | 你好，前提是“发言者”精确等于消息发送者的实际名字 |
| 你好，小明！ | 你好，小明！；正文中的提及保留 |
| 小明子: 你好 | 不触发 |
| [小明]: | 不触发，去掉称呼后没有正文 |

开头的称呼还支持名字后跟逗号或空格。只剥离开头的称呼，保留正文含义；已知发送者的精确 [发送者]: 包装可以先剥离，再处理对自己的称呼。未知发送者包装不会被擅自剥离。

仅提及已断开的 dummy 名字不会触发回复，除非该名字同时也是当前有效的自己名字。自己或已连接 dummy 发出的消息不会触发 AI，避免回复循环。

## 上下文与清空

关闭上下文时，每次请求仅包含系统提示词和当前正文，不携带历史对话。

开启上下文时，每位玩家最多保留配置数量的完整“玩家正文 → 已发送 AI 回复”对话轮次，默认 6 轮。这个上限按该玩家的总量计算，公共与队伍频道合计也不会超出；请求只使用同一频道的历史，避免将队伍聊天历史带入公共聊天请求。失败、取消或未发送的回复不写入上下文。

上下文只保存在内存中。关闭 AI、断开连接、组件重置或修改相关 AI 设置会清空历史并取消待处理回复。玩家离开、更换名字或进入被忽略状态时，会丢弃不再适用的待处理回复。

“清空上下文”按钮会清空所有玩家历史，并取消排队及进行中的回复，防止迟到的结果重新写入历史。清空后仍遵守已有冷却时间。

## 请求、频道与状态

- 网络请求异步执行，游戏线程不会等待 HTTP 请求完成。
- 同时最多进行一个请求，等待队列最多 8 条。同一玩家、同一频道的排队消息可被后续合格消息替换。
- 排队超过 120 秒的消息丢弃；HTTP 请求有连接、总耗时及响应大小限制。
- 冷却用于限制新提及的接收、请求启动和回复发送。配置为 0 时，请求及回复仍保持至少 1 秒间隔。
- 公共消息回复到公共频道，队伍消息回复到原队伍频道。等待期间切换操控连接或更换队伍后，不发送已经过期的回复。
- 忽略自己、dummy、无效玩家 ID、未知／离开的玩家、静音／忽略玩家和 demo 播放中的消息；也遵守好友、队伍及正则聊天过滤设置。
- 私聊消息不通过 SendChat 转发，防止把私人回复发到公共频道。
- 回复会清理控制字符并合并换行，最多 255 字节，截断不会破坏 UTF-8 字符。以斜杠命令开头的回复加上 [AI] 前缀，作为普通聊天发送。

设置页“状态”会显示是否关闭、等待提及、已排队、正在请求、等待冷却、已发送或请求失败。切换 dbg_http 不会暂停 AI，也不会因这个开关变化清空上下文。AI 请求始终使用 HTTPLOG::NONE；HTTP 引擎负责使这些请求在全局 HTTP 调试开启时也不输出 URL、请求头或密钥。

遇到请求失败时，检查协议、完整请求路径、模型名及服务认证要求。无效或空回复只显示通用状态，不把上游错误内容发送到游戏聊天。

## 测试入口

纯解析／协议测试位于 src/test/ai_reply_test.cpp，覆盖 Unicode 精确提及、称呼／已知发送者包装剥离、误提及、请求 JSON、双协议响应、长请求头、端点长度、上下文边界及 UTF-8／命令防护。构建 testrunner 后可用以下筛选运行：

~~~text
--gtest_filter=AiReply.*
~~~
